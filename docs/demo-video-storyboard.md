> 用途：赛事答辩 / 作品提交用演示视频（5–8 分钟，1080p MP4）

> 用一条可复现的链路证明「这是真后端，不是前端仿真」。

## 三、核心链路详解（一镜到底，禁止剪辑）

### 关键帧 1：登录 → 刷新不掉线（00:25–00:50）

1. 落地页点「快速体验」；
2.  toast「已使用演示账号登录（后端 VIP）」；
3.  **立刻按 F5**，停留 2 秒展示仍在工作台；
4. （可选加拍）点右上角头像 → 退出 → 再用**邮箱密码**登录一次，证明后端账号体系双向可用。

> 翻车预案：若刷新后回到登录页，说明 `enterApp` 落库逻辑被破坏——**不要录**，先修。

### 关键帧 2：五轮面试（01:20–04:30）

- 回答策略：**前两轮简短、第三轮给出量化数据、第四轮触发连环追问、第五轮简短**，让五维分数有区分度（表达分会因口头禅/短答下降，正好展示评分敏感度）；
- 每轮之间停顿 1–2 秒等流式输出完，别抢话；
- 右侧时间线出现「🌐 后端 glm-4-flash @ localhost:8000 · stream=true」时停顿半秒——这是后端在工作的肉眼证据。

### 关键帧 3：报告页徽章（04:30–05:20）

- 报告生成后**鼠标悬停在「服务端评分引擎 · 已落库」徽章上 2 秒**；
- 向下滚到「评分证据」区，展示至少两条引用原话；
- 再滚到顶部总分，念出分数。

### 关键帧 4：sqlite 三连（05:20–06:10）

```bash
sqlite3 backend/futuremirror.db "select count(*) from turns"
# 5
sqlite3 backend/futuremirror.db "select id, mode, status from interviews"
# iv_xxx|tech|finished
sqlite3 backend/futuremirror.db "select interview_id, total from reports"
# iv_xxx|78        ← 与页面综合得分一致
```

- 每条命令输出后停 1 秒；
- **总分必须和报告页一致**——提前对一遍，不一致说明 report 请求体丢了 `match_score/code_score`。

## 五、剪辑与包装要点

- **节奏**：面试段（01:20–04:30）不剪，保留真实感；其余段 1.5–2 倍速可接受，但 sqlite 段必须原速；
- **字幕**：关键帧 1/3/4 加放大字幕（「刷新不掉线」「服务端评分 · 已落库」「sqlite 查得到」）；
- **强调手段**：徽章和 sqlite 输出用「矩形描边 + 轻微放大」高亮 2 秒；
- **BGM**：60–80 BPM 底噪，面试段压低；
- **片头片尾**：片头 3 秒产品名 + 定位；片尾 GitHub 地址 + 测试数量。

## 六、翻车点预案

| 风险 | 现象 | 预案 |
|-----|------|------|
| 后端没起来 | 徽章显示「启发式引擎演示」 | 重录；这是底线问题，Mock 版视频没有说服力 |
| CORS 报错 | Network 面板红色 `/api/health` | 确认是 http:// 打开；检查 `.env` 的 `CORS_ORIGINS` |
| sqlite 分数不一致 | reports.total ≠ 页面分 | 检查 report 请求体是否带 `match_score/code_score/match_gaps` |
| 刷新掉线 | 关键帧 1 回到登录页 | 停止录制，检查 `enterApp` 是否写入本地用户表 |
| 流式卡住 | 回答停在中途 | 等 60s 超时机制兜底；或改用后端未配 Key 的形态录面试段（徽章会变，不可） |
| 向量模型下载慢 / 失败 | 状态条停在「模型权重下载中 43%」或变红提示 CDN 不可达 | **开录前先点一次**让浏览器缓存好权重（检查单第 8 项）；现场若失败就顺势讲「离线兜底是 n-gram hashing 向量，检索链路不中断」——降级本身也是设计点 |
| 穿帮 | 书签栏 / 其他标签页 / 微信消息 | 无痕窗口 + 录屏前开免打扰 |
